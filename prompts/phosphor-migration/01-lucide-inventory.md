# Book-site icon consumer inventory

## 1. Objective

Inventory current icon packages, wrappers and consumers before proposing any migration.

## 2. Inputs and scope

[repository instructions](../../AGENTS.md); [guideline reading order](../../guidelines/README.md); [book brief](../../content/book/this-one-time-on-acid-brief.md); [registered routes](../../src/app/routes.ts); [package manifest](../../package.json).

Inputs: actual src/app icon modules and consumers, package manifest/lockfile, bundler guidance, approved design tokens and current route inventory. Confirm paths before relying on historical examples.

Read current evidence before following historical path examples. This is a React/TypeScript/Vite book website, not a WordPress runtime or makeup-portfolio rebuild. Retain sourced memoir material without restoring its former page architecture.

## 3. Audit steps

1. Locate actual icon modules/wrappers, package declarations, shared exports and route/component consumers. Record paths, imported names/aliases, type-only imports and re-exports; historical totals of 96/77 or one legacy icon are not current facts.

2. Trace direct imports, central maps, string-based icon names, conditional/dynamic consumers, docs/examples and build/runtime package resolution. Zero direct imports does not prove an icon dependency is unused.

3. For each consumer, record purpose, decorative/informative/interactive role, visible label, props, size, stroke/weight, colour/currentColor, states and any animation. Identify protected or held surfaces without editing them.

4. Record actual package versions/export availability from repository evidence, distinguishing lockfile declarations from executed resolution. No installation, bundle measurement or migration is implicit.

5. Return a complete in-scope inventory and unresolved consumers, with sources and dependency risks; do not remove packages, edit wrappers or alter application imports.
