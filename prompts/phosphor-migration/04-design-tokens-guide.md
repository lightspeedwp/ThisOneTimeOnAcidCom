## 1. Objective

Assess current icon sizing, colour, state and weight conventions without publishing a new token system.

[repository instructions](../../AGENTS.md); [guideline reading order](../../guidelines/README.md); [book brief](../../content/book/this-one-time-on-acid-brief.md); [registered routes](../../src/app/routes.ts); [package manifest](../../package.json).

Read current evidence before following historical path examples. This is a React/TypeScript/Vite book website, not a WordPress runtime or makeup-portfolio rebuild. Retain sourced memoir material without restoring its former page architecture.

## 3. Audit steps

1. Inventory actual icon size/weight/colour tokens, CSS variables, wrappers and consumer overrides. Determine the current source of truth; do not introduce a new guide merely because a historical prompt requests one.

2. Compare dimensions, alignment, line-height, gaps, currentColor/inheritance and semantic states across real contexts. Preserve justified exceptions and distinguish visible icon size from interactive hit area.

3. Assess the actual package API for weights, fill/duotone rendering and supported props. Link exact consumer mappings and evidence instead of assuming a universal replacement.

4. Check BEM conventions, both themes, accessible names/decorative hiding, contrast and reduced motion. Proposed new tokens require demonstrated reuse and separate design approval; do not choose colours or fonts from the former makeup site.

5. Return a current-versus-proposed token/usage table and exact documentation candidates with gaps. Do not edit guidelines, styles, components or packages.
